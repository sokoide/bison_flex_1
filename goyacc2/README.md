# Goyacc2

* Second step: multiple statements per run (`stmts`/`stmt`), whitespace handling, and more tokens lexed than the grammar uses

Builds on [goyacc1](../goyacc1). This is the same single-file pipeline (main.go → lexer.go → y.go), plus:

## What this step adds over goyacc1

* `program: stmts` and `stmts: stmts stmt | /* empty */` — the input can now
  hold several statements, each printing its own `Result:`.
  The empty `stmts` rule is also the first example of a reduce on EOF.
* `isWhiteSpace()` — the lexer now skips ' ', '\t', '\n' at the top of the
  `Lex()` loop, so input may be formatted freely (goyacc1's lexer now does the
  same, but goyacc2 is the first step where statements span lines).
* New tokens lexed: `'='`, `';'`, `'{'`, `'}'` are returned by the lexer but
  NOT used by any rule here. That is deliberate: the parser output for them
  is `syntax error`, showing that the lexer/grammar must agree only on what
  the grammar uses — and they are staged for goyacc2b/2c.
* `%` is lexed and given a rule: `expr '%' expr { $$ = $1 % $3 }`.
* `IDENT` ([a-z]+) is lexed but not accepted by the grammar yet, so
  `a=3;` fails to parse. Variables arrive in goyacc2b.

## Teaching points

* The `%%` trick in test: in a Make recipe `%%` of printf is needed because
  `printf '20%7 +...'` would eat `%7` as a format spec.
* `yyErrorVerbose = true` is set in `lexer.go`'s `init()`. Run
  `printf '1+' | ./hoge` to see the verbose form
  (`unexpected $end, expecting NUMBER or '('`) instead of plain
  `syntax error`. When something is off in a grammar, this is the message
  to study first.
* main.go now checks `yyParse()`'s return value and exits non-zero on failure.

## Files

* hoge.go.y ... grammar file
* y.go/y.output ... generated by `goyacc`
* lexer.go ... hand-written lexer
* main.go ... reads stdin, feeds the lexer, runs `yyParse`
