# Goyacc2b

* Third step: variables, assignment, a `PUT(...)` statement and `%` in the grammar

Builds on [goyacc2](../goyacc2). Same three-file layout (main.go, lexer.go, y.go).

## What this step adds over goyacc2

* `stmt: IDENT '=' expr ';'` — an assignment statement. The action stores it
  in a global `vars` map declared in the epilogue (the section after the
  final `%%`): `var vars = map[string]int{}`.
* `stmt: PUT '(' expr ')' ';'` — a print statement. `put` is special-cased
  in `getString()`: the lexer looks the word up and returns the `PUT` token
  instead of `IDENT` (a hand-written keyword lookup).
* `expr: IDENT { $$ = vars[$1] }` — reading a variable. Known quirk:
  an undefined variable reads as 0 (no diagnostics).
* `expr '%' expr` now really lands in the grammar (goyacc2 lexed `%` too;
  here it can be combined with assignment: `a=20%7`).
* Staged tokens `'{' '}'` are still unused here — they are consumed by
  goyacc2c's `if`.

## Teaching point: keyword handling in a hand-written lexer

Because the lexer is code you own, "keywords" need no extra machinery:
when `getString()` produced the word `put`, return `PUT`; otherwise return
`IDENT`. Compare with real languages where keywords are usually a map.

Semantic actions still run DURING parsing, exactly like goyacc1/2 —
that is why `1/0` panics mid-parse inside the grammar action.
goyacc2c shows the AST alternative.

## Files

* hoge.go.y ... grammar; note the `var vars` map in the epilogue after `%%`
* y.go/y.output ... generated by `goyacc`
* lexer.go ... hand-written lexer (`PUT` vs `IDENT` dispatch)
* main.go ... reads stdin, feeds the lexer, runs `yyParse`
