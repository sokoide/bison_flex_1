# Goyacc2c

> 日本語版: [README_ja.md](README_ja.md)

* Fourth step: build an AST during parsing, evaluate after `yyParse` returns, and add `if`

Builds on [goyacc2b](../goyacc2b). Same files plus `ast.go`, and the shift of
evaluation out of the grammar actions.

## What this step adds over goyacc2b

* `ast.go` — a small universal `Node{Kind, S, I, N1, N2, Ns}` tree plus
  `evaluate()`/`evaluateNode()`. String kinds double as the node type, so
  there is no separate node struct per rule (`newNode("+", "", 0, $1, $3, nil)`).
* Grammar actions no longer compute anything: they only build nodes
  (`%type<node>`/`%type<nodes>` instead of `%type<val>`), and the
  `if` statement becomes a rule:
  `stmt: IF '(' expr ')' '{' stmts '}'`. This is why lexer staged the `'{'`
  `'}'` tokens back in goyacc2.
* Evaluation is deferred: `main()` runs `evaluate(lexer)` AFTER
  `yyParse(lexer)` returns.

## Why defer evaluation? The `1/0` teaching point

In goyacc1/2/2b the actions run DURING parsing, so a division by zero
panics mid-parse, inside the `expr '/' expr` action — while the parser is
still on the stack. You would not get an error return from `yyParse` (the
panic bypasses it).

In goyacc2c parsing only builds the tree, so `yyParse` returns normally and
the panic (if any) happens later, in the evaluator:

```
$ printf 'put(1/0);\n' | ./hoge
panic: runtime error: integer divide by zero
    ... ast.go:53 (evaluateNode), called from evaluateNodes ...
```

Same input, two different crash sites — that difference *is* the lesson:
parse and execution are now cleanly separated, which is exactly the shape
needed later for interpreter optimizations, byte code, or backends.

## Build / Run / Test

```
make          # goyacc hoge.go.y -> y.go, then build ./hoge
make test     # exact assertions, exits non-zero on mismatch
make run      # read statements from stdin
make clean    # removes ./hoge y.go y.output
```

## Handing the tree back to the caller

The program non-terminal's result has to reach `main()`. The trick:
`program: stmts { $$ = $1; yylex.(*lexer).program = $$ }` casts the
`yylex` interface argument back to the concrete `*lexer` pointer, whose
`program []*Node` field main() then reads. (The cast works because goyacc
requires the caller's type to implement the `yylex` interface.)

Same as before: assignment/put now store nodes and print at evaluation
time; undefined variables still read as 0; no unary minus; identifiers
are lowercase `[a-z]+` only.

## Files

* hoge.go.y ... grammar (state machine only; no side effects in actions)
* y.go/y.output ... generated by `goyacc`
* lexer.go ... hand-written lexer (`PUT`, `IF` keyword dispatch)
* ast.go ... the Node type and the post-parse evaluator
* main.go ... reads stdin, parses, then evaluates
